O split por cobrança permite definir **para quem e quanto repassar em cada QR Code**, no momento em que você cria a cobrança. Quando o pagador paga, a Delfinance credita o valor integral na conta de recebimento e, em seguida, repassa automaticamente as partes definidas para cada beneficiário, seja uma conta Delfinance ou uma conta em outro banco.

Os termos **conta de recebimento**, **beneficiário**, **conta do beneficiário** e **repasse** seguem os [conceitos do Split de Pagamentos](/guias/split-pagamentos/visao-geral#conceitos).

A diferença para o [split padrão da conta](/guias/split-pagamentos/configurar) é o escopo:

| | Split padrão da conta | Split por cobrança |
|---|---|---|
| Onde a regra é definida | Configuração da conta (`/split-payments/configurations`) | Campo `splitPayment` na criação do QR Code |
| A quem se aplica | Todo Pix recebido na conta | Apenas os pagamentos daquele QR Code |
| Beneficiários diferentes por venda | Não | Sim |
| Formas de repasse | `INTERNAL` e `PIX_MANUAL` | `INTERNAL`, `PIX_MANUAL` e `PIX_KEY` |

<Tip>
Use o split por cobrança quando cada venda tem um destinatário diferente. Por exemplo: em um marketplace, cada pedido é de um vendedor, e a parte de cada vendedor é repassada no próprio QR Code do pedido.
</Tip>

## Como funciona

```mermaid
sequenceDiagram
    participant S as Seu sistema
    participant D as Delfinance
    participant P as Pagador
    S->>D: POST /pix/qrcode/dynamic com splitPayment
    D-->>S: QR Code (payloadPix) + splitPayment
    S->>P: Exibe o QR Code
    P->>D: Paga o Pix
    D->>D: Credita o valor integral na conta de recebimento
    D-->>S: Webhook PIX_RECEIVED
    D->>D: Calcula e executa cada repasse
    D-->>S: Webhooks dos repasses (transferência interna ou Pix enviado)
```

1. Você cria o QR Code dinâmico com as instruções de repasse em `splitPayment.instructions`.
2. A Delfinance valida as instruções e as guarda junto com a cobrança.
3. Quando o Pix é pago, o valor **integral** entra na conta que criou o QR Code.
4. Logo depois, a Delfinance calcula o valor de cada instrução e transfere da conta de recebimento para cada beneficiário: por transferência interna (`INTERNAL`) ou por Pix, com dados bancários (`PIX_MANUAL`) ou com chave Pix (`PIX_KEY`).
5. O que não foi destinado a nenhuma instrução permanece na conta de recebimento.

<Note>
O split por cobrança está disponível apenas na [Cobrança Imediata (QR Code Dinâmico)](/guias/pix/receber-pix/cobranca-imediata). A cobrança com vencimento e o QR Code estático não aceitam `splitPayment`.
</Note>

## Passo a passo

<Steps>

<Step title="Crie o QR Code com as instruções de split">
Envie o objeto `splitPayment` junto com os demais dados da cobrança. Cada item de `instructions` é um repasse.

No exemplo abaixo, um pedido de R\$ 200,00 repassa 10% para a conta Delfinance do vendedor e R\$ 5,00 fixos, via Pix, para a conta de um afiliado em outro banco.

```bash cURL
curl --location 'https://apisandbox.delbank.com.br/baas/api/v2/pix/qrcode/dynamic' \
--header 'Content-Type: application/json' \
--header 'x-delbank-api-key: {{apiKey}}' \
--header 'x-delfinance-account-id: {{accountId}}' \
--data '{
    "correlationId": "{{$guid}}",
    "amount": 200.00,
    "expiresIn": 1800,
    "formatResponse": "PAYLOAD_AND_QRCODE",
    "splitPayment": {
        "instructions": [
            {
                "amount": 10,
                "type": "PERCENTAGE",
                "transferType": "INTERNAL",
                "beneficiary": {
                    "number": "10073"
                }
            },
            {
                "amount": 5.00,
                "type": "FIXED",
                "transferType": "PIX_MANUAL",
                "beneficiary": {
                    "number": "123456",
                    "branch": "0001",
                    "type": "CURRENT",
                    "participantIspb": "00000000",
                    "holder": {
                        "document": "12345678909",
                        "name": "Maria Souza",
                        "type": "NATURAL"
                    }
                }
            }
        ]
    }
}'
```

O header `x-delfinance-account-id` define a **conta de recebimento**: a conta que recebe o pagamento e de onde saem os repasses.
</Step>

<Step title="Confira a resposta">
A resposta é a mesma da criação de um QR Code dinâmico comum. O objeto `splitPayment` volta com as instruções registradas, para você confirmar o que foi gravado.

```json
{
    "correlationId": "40ede975-031d-4517-bdd4-31472d3f00a4",
    "transactionId": "vchargeffab8b4c963344c283e491f5e",
    "amount": 200.00,
    "expiresIn": 1800,
    "status": "ACTIVE",
    "payloadPix": "00020101021226820014br.gov.bcb.pix2560pix-h.delbank.com.br/v2/cob/...",
    "qrCodeImageBase64": "data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAPoA...",
    "splitPayment": {
        "canChargeTariffBeforeSplit": true,
        "instructions": [
            {
                "amount": 10,
                "type": "PERCENTAGE",
                "transferType": "INTERNAL",
                "beneficiary": { "number": "10073" }
            },
            {
                "amount": 5.00,
                "type": "FIXED",
                "transferType": "PIX_MANUAL",
                "beneficiary": {
                    "number": "123456",
                    "branch": "0001",
                    "type": "CURRENT",
                    "participantIspb": "00000000",
                    "holder": {
                        "document": "12345678909",
                        "name": "Maria Souza",
                        "type": "NATURAL"
                    }
                }
            }
        ]
    }
}
```

Se alguma instrução não respeitar as [regras de validação](#regras-de-validação), o QR Code não é criado e a API retorna o erro `INVALID_SPLIT` com a lista de problemas encontrados.
</Step>

<Step title="Exiba o QR Code para o pagador">
Use o `payloadPix` (copia e cola) ou o `qrCodeImageBase64` normalmente. Para o pagador, nada muda: ele vê e paga o valor total da cobrança.
</Step>

<Step title="Acompanhe o recebimento e os repasses pelos webhooks">
Quando o Pix é pago, você recebe um evento [`PIX_RECEIVED`](/guias/webhooks/pix) com o valor integral. Em seguida, cada repasse gera os eventos da forma de transferência usada:

- **`INTERNAL`**: um [`TRANSFER_INTERNAL_DEBITED`](/guias/webhooks/transferencias) na conta de recebimento. Se a conta do beneficiário tiver webhook configurado, ela recebe um `TRANSFER_INTERNAL_CREDITED`.
- **`PIX_MANUAL` e `PIX_KEY`**: um [`PIX_PAYMENT_UPDATED`](/guias/webhooks/pix) com o status do Pix enviado ao beneficiário.
</Step>

</Steps>

## Campos de `splitPayment`

| Campo | Tipo | Obrigatório | Descrição |
|---|---|---|---|
| `canChargeTariffBeforeSplit` | `boolean` | Não | Quando `true` (padrão), a tarifa de split prevista no seu contrato é descontada do valor recebido antes do cálculo dos repasses. Veja [Como o valor de cada repasse é calculado](#como-o-valor-de-cada-repasse-é-calculado) |
| `instructions` | `array` | Sim | Lista de repasses. Deve ter pelo menos uma instrução |

### Instrução (`instructions[]`)

| Campo | Tipo | Obrigatório | Descrição |
|---|---|---|---|
| `amount` | `number` | Sim | Percentual ou valor do repasse, conforme o `type`. Deve ser maior que zero |
| `type` | `string` | Sim | `PERCENTAGE` (porcentagem do valor recebido) ou `FIXED` (valor fixo em reais) |
| `transferType` | `string` | Sim | `INTERNAL` (conta Delfinance), `PIX_MANUAL` (conta em qualquer instituição, por dados bancários) ou `PIX_KEY` (conta em qualquer instituição, por chave Pix) |
| `beneficiary` | `object` | Sim | Dados da conta do beneficiário |
| `daysUntilPayment` | `integer` | Não | Quantidade de dias corridos, contados a partir do pagamento, para fazer o repasse. `0` repassa logo após o pagamento. Não pode ser usado com `paymentDate`. Veja [Agendar um repasse](#agendar-um-repasse) |
| `paymentDate` | `string` | Não | Data fixa do repasse, no formato `YYYY-MM-DD`. Sem o campo, ou com a data de hoje, o repasse é feito logo após o pagamento. Com uma data futura, o repasse é agendado. Não pode ser usado com `daysUntilPayment` |

### Beneficiário (`beneficiary`)

O `beneficiary` segue o mesmo formato de conta usado no Pix manual e no split padrão da conta. Com `PIX_KEY`, a conta é identificada pela chave Pix, no lugar dos dados bancários. Os campos obrigatórios dependem do `transferType`.

| Campo | Tipo | `INTERNAL` | `PIX_MANUAL` | `PIX_KEY` | Descrição |
|---|---|---|---|---|---|
| `number` | `string` | Obrigatório | Obrigatório | — | Número da conta do beneficiário |
| `branch` | `string` | — | Obrigatório | — | Agência da conta do beneficiário |
| `type` | `string` | — | Obrigatório | — | Tipo da conta do beneficiário: `PAYMENT`, `CURRENT` ou `SAVING` |
| `participantIspb` | `string` | — | Obrigatório | — | ISPB da instituição de destino (8 caracteres) |
| `pixKey` | `string` | — | — | Obrigatório | Chave Pix do beneficiário: CPF, CNPJ, e-mail, telefone (`+55...`) ou chave aleatória |
| `holder` | `object` | — | Obrigatório | Obrigatório | Titular da conta do beneficiário |
| `holder.document` | `string` | — | Obrigatório | Obrigatório | CPF ou CNPJ do titular, somente números |
| `holder.name` | `string` | — | Obrigatório | Obrigatório | Nome do titular |
| `holder.type` | `string` | — | Obrigatório | Obrigatório | `NATURAL` (pessoa física) ou `LEGAL` (pessoa jurídica) |

<Tabs>
  <Tab title="INTERNAL">
    Para repassar para uma conta Delfinance, basta o número da conta.

    ```json
    {
        "amount": 10,
        "type": "PERCENTAGE",
        "transferType": "INTERNAL",
        "beneficiary": {
            "number": "10073"
        }
    }
    ```
  </Tab>
  <Tab title="PIX_MANUAL">
    Para repassar para uma conta em qualquer instituição, informe os dados bancários completos do beneficiário. O repasse é feito por um Pix saindo da conta de recebimento.

    ```json
    {
        "amount": 5.00,
        "type": "FIXED",
        "transferType": "PIX_MANUAL",
        "beneficiary": {
            "number": "123456",
            "branch": "0001",
            "type": "CURRENT",
            "participantIspb": "00000000",
            "holder": {
                "document": "12345678909",
                "name": "Maria Souza",
                "type": "NATURAL"
            }
        }
    }
    ```
  </Tab>
  <Tab title="PIX_KEY">
    Para repassar para uma conta em qualquer instituição sem pedir os dados bancários ao beneficiário, informe a chave Pix dele e o titular. O repasse é feito por um Pix saindo da conta de recebimento.

    ```json
    {
        "amount": 5.00,
        "type": "FIXED",
        "transferType": "PIX_KEY",
        "beneficiary": {
            "pixKey": "12345678909",
            "holder": {
                "document": "12345678909",
                "name": "Maria Souza",
                "type": "NATURAL"
            }
        }
    }
    ```

    No momento do repasse, a Delfinance consulta a chave no DICT (o diretório de chaves do Pix) para encontrar a conta. O repasse só é enviado se o titular da chave tiver o mesmo CPF ou CNPJ informado em `holder.document`. Assim, uma chave digitada errado não manda o dinheiro para outra pessoa.
  </Tab>
</Tabs>

## Agendar um repasse

Por padrão, cada repasse é feito logo após o pagamento. Um uso comum para agendar: o marketplace só libera a parte do vendedor depois do prazo de entrega ou de devolução do produto.

Há duas formas de agendar. Informe uma ou outra na instrução, nunca as duas:

| Campo | Tipo | Quando usar |
|---|---|---|
| `daysUntilPayment` | `integer` | Para repassar uma quantidade de dias **depois do pagamento**. É a forma mais comum, porque você não sabe quando o cliente final vai pagar. A data do repasse é calculada quando o Pix é recebido: data do pagamento + dias corridos |
| `paymentDate` | `string` | Para repassar numa **data fixa**, no formato `YYYY-MM-DD`, independente de quando o pagamento acontecer |

<Tabs>
  <Tab title="daysUntilPayment">
    No exemplo abaixo, o vendedor recebe R\$ 54,00 30 dias depois do pagamento. Se o cliente final pagar em 03/11/2026, o repasse é feito em 03/12/2026.

    ```json
    {
        "amount": 54.00,
        "type": "FIXED",
        "transferType": "INTERNAL",
        "daysUntilPayment": 30,
        "beneficiary": {
            "number": "10073"
        }
    }
    ```
  </Tab>
  <Tab title="paymentDate">
    No exemplo abaixo, o vendedor recebe R\$ 54,00 em 27/11/2026, e não no momento do pagamento.

    ```json
    {
        "amount": 54.00,
        "type": "FIXED",
        "transferType": "INTERNAL",
        "paymentDate": "2026-11-27",
        "beneficiary": {
            "number": "10073"
        }
    }
    ```
  </Tab>
</Tabs>

O comportamento depende da data do repasse:

| Data do repasse | Status inicial do repasse | Quando o repasse é feito |
|---|---|---|
| Sem `paymentDate` nem `daysUntilPayment`, `daysUntilPayment` igual a `0`, ou `paymentDate` igual ou anterior à data do pagamento | `PENDING` | Logo após o pagamento |
| Data futura | `SCHEDULED` | Automaticamente, na data |

Nos dois casos, a data calculada aparece em `paymentDate` nas consultas de repasses.

Enquanto o repasse está agendado, você pode [cancelá-lo, pausá-lo ou mudar a data](/api-reference/split-pagamentos/atualizar-repasse), ou antecipá-lo com o [reprocessamento](/api-reference/split-pagamentos/reprocessar-repasses). Acompanhe os repasses agendados em [Acompanhar repasses](/guias/split-pagamentos/acompanhar-repasses).

<Warning>
Até a data do repasse, o valor fica na conta de recebimento. Mantenha saldo suficiente para os repasses agendados: se faltar saldo na data, o repasse termina em `ERROR` e precisa ser reprocessado.
</Warning>

<Note>
O agendamento só está disponível no split por cobrança. No split padrão da conta, os repasses são sempre feitos logo após o pagamento.
</Note>

## Regras de validação

As regras abaixo são verificadas na criação do QR Code. Se qualquer uma falhar, a cobrança não é criada e a API retorna `INVALID_SPLIT`.

| Regra | Limite |
|---|---|
| Valor da cobrança (`amount`) | Pelo menos R$ 1,00 |
| Quantidade de instruções | Pelo menos uma |
| `amount` de cada instrução | Maior que zero |
| Cada instrução `PERCENTAGE` | Até 100% |
| Soma de todos os repasses (percentuais convertidos em reais + valores fixos) | Até o valor da cobrança |
| Campos do `beneficiary` | Conforme o `transferType`, veja a tabela acima |
| `paymentDate`, quando informado | Data válida, no formato `YYYY-MM-DD`, igual ou posterior à data de criação do QR Code |
| `daysUntilPayment`, quando informado | Número inteiro maior ou igual a `0` |
| `paymentDate` e `daysUntilPayment` | Não podem ser informados juntos na mesma instrução |

<Note>
Os dados do beneficiário não são verificados na criação do QR Code. Confira o número da conta, os dados bancários ou a chave Pix antes de enviar: um dado incorreto só aparece como falha no momento do repasse.
</Note>

## Como o valor de cada repasse é calculado

O cálculo acontece no momento em que o Pix é recebido:

- **`PERCENTAGE`**: aplica o percentual sobre o valor recebido e arredonda para 2 casas decimais.
- **`FIXED`**: repassa exatamente o valor informado.

Usando o exemplo do passo a passo, com uma cobrança de R$ 200,00 e sem tarifa de split:

```mermaid
flowchart LR
    A["Pix recebido<br/>R$ 200,00"] --> B["Conta de recebimento"]
    B --> C["Conta 10073 (INTERNAL)<br/>PERCENTAGE 10% = R$ 20,00"]
    B --> D["Maria Souza (PIX_MANUAL)<br/>FIXED = R$ 5,00"]
    B --> E["Fica na conta de recebimento<br/>R$ 175,00"]
```

### Tarifa antes do split

Com `canChargeTariffBeforeSplit` igual a `true` (padrão), a tarifa de split prevista no seu contrato é descontada do valor recebido **antes** do cálculo. Os percentuais passam a incidir sobre o valor líquido.

Por exemplo: com uma tarifa de R\$ 2,00, a base de cálculo da cobrança de R\$ 200,00 passa a ser R\$ 198,00, e os 10% viram R\$ 19,80.

<Warning>
Se a soma dos repasses ultrapassar o valor líquido (depois da tarifa), **nenhum** repasse daquele pagamento é executado, e o valor integral permanece na conta de recebimento. Deixe uma margem para a tarifa quando usar valores fixos próximos do valor da cobrança.
</Warning>

## Comportamentos importantes

<AccordionGroup>
  <Accordion title="O split da cobrança substitui o split padrão da conta">
    Se a conta de recebimento também tem um [split padrão](/guias/split-pagamentos/configurar), ele **não** é aplicado aos pagamentos de um QR Code com `splitPayment`. Para esses pagamentos, valem apenas as instruções da cobrança. Os demais Pix recebidos na conta continuam seguindo o split padrão.
  </Accordion>
  <Accordion title="Conta Delfinance inexistente">
    Se o `beneficiary.number` de uma instrução `INTERNAL` não corresponder a uma conta Delfinance, aquele repasse não é executado e o valor permanece na conta de recebimento. O pagamento do Pix não é afetado.
  </Accordion>
  <Accordion title="Pix de repasse rejeitado">
    Em uma instrução `PIX_MANUAL` ou `PIX_KEY`, se o Pix para o beneficiário for rejeitado (por exemplo, por dados bancários incorretos), o valor não é repassado e o erro chega no evento `PIX_PAYMENT_UPDATED`.
  </Accordion>
  <Accordion title="Chave Pix inexistente ou de outro titular">
    Em uma instrução `PIX_KEY`, se a chave não existir no DICT ou pertencer a um CPF ou CNPJ diferente de `holder.document`, o Pix não é enviado. O repasse termina em `ERROR`, com o motivo em `errorMessage`, e o valor permanece na conta de recebimento. Como os dados do beneficiário não podem ser alterados depois, [cancele o repasse](/api-reference/split-pagamentos/atualizar-repasse) e acerte o valor com o beneficiário pela sua plataforma.
  </Accordion>
  <Accordion title="Momento do repasse">
    Sem `paymentDate` nem `daysUntilPayment`, o repasse é feito logo após o crédito do Pix. Com uma data futura, informada em `paymentDate` ou calculada por `daysUntilPayment`, o repasse fica agendado (`SCHEDULED`) e é feito automaticamente na data. Veja [Agendar um repasse](#agendar-um-repasse).
  </Accordion>
  <Accordion title="Consulta dos repasses">
    Para ver os repasses gerados por uma cobrança, o status de cada um e o valor a receber de cada beneficiário, use as consultas de [Acompanhar repasses](/guias/split-pagamentos/acompanhar-repasses) (em beta).
  </Accordion>
</AccordionGroup>

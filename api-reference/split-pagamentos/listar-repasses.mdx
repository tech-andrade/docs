---
title: "Listar repasses"
api: "GET /baas/api/v1/split-payments/payouts"
description: "Liste os repasses da conta de recebimento, com filtros por beneficiário, status, forma de repasse e datas."
tag: "BETA"
---

<Warning>
**Funcionalidade em beta.** Contrato em proposta, sujeito a mudanças. Veja o guia [Acompanhar repasses](/guias/split-pagamentos/acompanhar-repasses).
</Warning>

Retorna, de forma paginada, os repasses (*payouts*) de todas as ordens de recebimento com split da conta de recebimento. Use o filtro `beneficiaryDocument` para mostrar a um beneficiário o histórico dos repasses dele.

## Headers

<ParamField header="x-delbank-api-key" type="string" required>
  Sua API key.
</ParamField>

<ParamField header="x-delfinance-account-id" type="string" required>
  Número da conta de recebimento.
</ParamField>

## Query params

Todos os filtros são opcionais e podem ser combinados.

<ParamField query="beneficiaryDocument" type="string">
  CPF ou CNPJ do beneficiário, somente números.
</ParamField>

<ParamField query="beneficiaryId" type="string">
  Id (UUID) do beneficiário no [cadastro de beneficiários](/guias/split-pagamentos/beneficiarios). Traz todos os repasses dele, inclusive os criados antes de uma mudança na conta.
</ParamField>

<ParamField query="beneficiaryName" type="string">
  Nome do beneficiário. Aceita parte do nome.
</ParamField>

<ParamField query="status" type="string">
  Status do repasse: `SCHEDULED`, `PENDING`, `HOLDING`, `PROCESSING`, `SUCCESS`, `ERROR`, `CANCELED` ou `REFUNDED`.
</ParamField>

<ParamField query="transferType" type="string">
  Forma do repasse: `INTERNAL`, `PIX_MANUAL` ou `PIX_KEY`.
</ParamField>

<ParamField query="startDate" type="string">
  Data inicial de criação do repasse, no formato `YYYY-MM-DD`.
</ParamField>

<ParamField query="endDate" type="string">
  Data final de criação do repasse, no formato `YYYY-MM-DD`.
</ParamField>

<ParamField query="paymentDateFrom" type="string">
  Data inicial prevista para o repasse (`paymentDate`), no formato `YYYY-MM-DD`.
</ParamField>

<ParamField query="paymentDateTo" type="string">
  Data final prevista para o repasse (`paymentDate`), no formato `YYYY-MM-DD`.
</ParamField>

<ParamField query="page" type="number" default="1">
  Número da página (começa em 1).
</ParamField>

<ParamField query="limit" type="number" default="20">
  Itens por página. Máximo de 100.
</ParamField>

## Response

Array de repasses. Os dados de paginação vêm no header `Pagination`, descrito em [Paginação](#paginação).

Os campos `status`, `transferType`, `instructionType` e `order.source` são enums retornados como objeto, com `name`, `description` e `value`. Veja [Formato dos enums](/guias/split-pagamentos/acompanhar-repasses#formato-dos-enums).

<ResponseField name="id" type="string">
  Identificador do repasse. Use-o para [reprocessar](/api-reference/split-pagamentos/reprocessar-repasses) ou [atualizar](/api-reference/split-pagamentos/atualizar-repasse) o repasse (cancelar, pausar, liberar ou mudar a data).
</ResponseField>
<ResponseField name="order" type="object">
  Ordem de recebimento com split que gerou o repasse. Mostra o valor integral do pagamento, a origem das instruções e a base de cálculo, sem precisar de outra consulta. É o mesmo recurso retornado por [Consultar ordem de recebimento com split](/api-reference/split-pagamentos/consultar-recebimento).

  <Expandable title="order">
    <ResponseField name="id" type="string">Identificador da ordem de recebimento com split: o id da transação de crédito, o mesmo do extrato e do webhook de recebimento. Use-o em [Consultar ordem de recebimento com split](/api-reference/split-pagamentos/consultar-recebimento).</ResponseField>
    <ResponseField name="source" type="object">Origem das instruções. `name`: `ACCOUNT_CONFIGURATION` (split padrão da conta) ou `QR_CODE` (split por cobrança).</ResponseField>
    <ResponseField name="grossAmount" type="number">Valor integral do pagamento recebido.</ResponseField>
    <ResponseField name="tariffAmount" type="number">Tarifa de split descontada antes do cálculo. `0` quando não há.</ResponseField>
    <ResponseField name="splitBaseAmount" type="number">Base de cálculo dos repasses (`grossAmount - tariffAmount`).</ResponseField>
    <ResponseField name="createdAt" type="string">Data e hora de criação da ordem, que coincide com o recebimento do pagamento, em ISO 8601.</ResponseField>
  </Expandable>
</ResponseField>
<ResponseField name="status" type="object">
  Status do repasse. `name`: `SCHEDULED`, `PENDING`, `HOLDING`, `PROCESSING`, `SUCCESS`, `ERROR`, `CANCELED` ou `REFUNDED`. Veja o significado de cada um em [Status do repasse](/guias/split-pagamentos/status-do-repasse).
</ResponseField>
<ResponseField name="transferType" type="object">
  Forma do repasse. `name`: `INTERNAL`, `PIX_MANUAL` ou `PIX_KEY`.
</ResponseField>
<ResponseField name="instructionType" type="object">
  Tipo da instrução que gerou o repasse. `name`: `PERCENTAGE` ou `FIXED`.
</ResponseField>
<ResponseField name="instructionAmount" type="number">
  Percentual ou valor definido na instrução.
</ResponseField>
<ResponseField name="amount" type="number">
  Valor do repasse, em reais: o valor calculado pela instrução, menos as [devoluções](/api-reference/split-pagamentos/devolver-repasse). É o valor que vai para a conta do beneficiário.
</ResponseField>
<ResponseField name="refundedAmount" type="number">
  Soma das devoluções do repasse, em reais. O valor calculado pela instrução é `amount + refundedAmount`. `0` quando não houve devolução.
</ResponseField>
<ResponseField name="paymentDate" type="string">
  Data prevista do repasse, no formato `YYYY-MM-DD`. É a data do recebimento, exceto quando a instrução de split do QR Code agenda o repasse para uma data futura, com `paymentDate` ou `daysUntilPayment` (data do recebimento + dias). Nesse caso, o repasse fica em `SCHEDULED` até a data. A data pode ser alterada em [Atualizar repasse](/api-reference/split-pagamentos/atualizar-repasse).
</ResponseField>
<ResponseField name="beneficiaryId" type="string">
  Id do beneficiário no [cadastro de beneficiários](/guias/split-pagamentos/beneficiarios), quando a instrução usou `beneficiaryId`. `null` quando a instrução enviou o `beneficiary` completo.
</ResponseField>
<ResponseField name="beneficiary" type="object">
  Conta do beneficiário, no mesmo formato usado nas transferências. Em repasses `PIX_KEY`, os dados da conta (`number`, `branch`, `type` e `participant`) vêm da consulta da chave no DICT e ficam `null` até o repasse ser executado.

  <Expandable title="beneficiary">
    <ResponseField name="pixKey" type="string">Chave Pix do beneficiário, em repasses `PIX_KEY`. `null` nas demais formas de repasse.</ResponseField>
    <ResponseField name="number" type="string">Número da conta do beneficiário.</ResponseField>
    <ResponseField name="branch" type="string">Agência da conta do beneficiário.</ResponseField>
    <ResponseField name="type" type="string">Tipo da conta do beneficiário: `PAYMENT`, `CURRENT` ou `SAVING`.</ResponseField>
    <ResponseField name="holder" type="object">
      Titular da conta, ou seja, o beneficiário.

      <Expandable title="holder">
        <ResponseField name="document" type="string">CPF ou CNPJ do beneficiário.</ResponseField>
        <ResponseField name="name" type="string">Nome do beneficiário.</ResponseField>
        <ResponseField name="type" type="string">`NATURAL` (pessoa física) ou `LEGAL` (pessoa jurídica).</ResponseField>
      </Expandable>
    </ResponseField>
    <ResponseField name="participant" type="object">
      Instituição da conta do beneficiário.

      <Expandable title="participant">
        <ResponseField name="ispb" type="string">ISPB da instituição.</ResponseField>
        <ResponseField name="name" type="string">Nome da instituição.</ResponseField>
      </Expandable>
    </ResponseField>
  </Expandable>
</ResponseField>
<ResponseField name="transactionId" type="string">
  Id da transferência que executou o repasse (transferência interna ou Pix). `null` enquanto o repasse não é executado.
</ResponseField>
<ResponseField name="endToEndId" type="string">
  Identificador do Pix, em repasses `PIX_MANUAL` e `PIX_KEY`.
</ResponseField>
<ResponseField name="errorMessage" type="string">
  Motivo da falha, quando o status é `ERROR`. Depois de corrigir a causa, você pode [reprocessar o repasse](/api-reference/split-pagamentos/reprocessar-repasses).
</ResponseField>
<ResponseField name="holdDetails" type="object">
  Dados da última pausa do repasse. `null` se o repasse nunca foi pausado.

  <Expandable title="holdDetails">
    <ResponseField name="heldBy" type="string">Quem pediu a pausa, como informado em `action.requestedBy`.</ResponseField>
    <ResponseField name="reason" type="string">Motivo informado na pausa.</ResponseField>
    <ResponseField name="heldAt" type="string">Data e hora da pausa, em ISO 8601.</ResponseField>
    <ResponseField name="releasedBy" type="string">Quem liberou o repasse. `null` enquanto o repasse está pausado.</ResponseField>
    <ResponseField name="releaseReason" type="string">Motivo informado na liberação, se houver.</ResponseField>
    <ResponseField name="releasedAt" type="string">Data e hora da liberação, em ISO 8601. `null` enquanto o repasse está pausado.</ResponseField>
  </Expandable>
</ResponseField>
<ResponseField name="cancellationDetails" type="object">
  Dados do cancelamento, quando o status é `CANCELED`. `null` nos demais casos.

  <Expandable title="cancellationDetails">
    <ResponseField name="canceledBy" type="string">Quem pediu o cancelamento, como informado em `action.requestedBy`.</ResponseField>
    <ResponseField name="reason" type="string">Motivo informado no cancelamento.</ResponseField>
    <ResponseField name="canceledAt" type="string">Data e hora do cancelamento, em ISO 8601.</ResponseField>
  </Expandable>
</ResponseField>
<ResponseField name="paidAt" type="string">
  Data e hora em que o repasse foi concluído, em ISO 8601.
</ResponseField>
<ResponseField name="createdAt" type="string">
  Data e hora de criação do repasse, em ISO 8601.
</ResponseField>
<ResponseField name="updatedAt" type="string">
  Data e hora da última mudança de status, em ISO 8601.
</ResponseField>

## Paginação

A resposta é um array. Os dados de paginação vêm no header `Pagination`:

```text Header
Pagination: {"currentPage":1,"pageSize":20,"pageCount":1,"rowCount":1,"totalAmount":5.00}
```

| Campo | Descrição |
|---|---|
| `currentPage` | Página retornada |
| `pageSize` | Itens por página (`limit`) |
| `pageCount` | Total de páginas |
| `rowCount` | Total de repasses encontrados |
| `totalAmount` | Soma do `amount` de todos os repasses encontrados, considerando todas as páginas |

```bash cURL
curl --location 'https://apisandbox.delbank.com.br/baas/api/v1/split-payments/payouts?beneficiaryDocument=12345678909&status=ERROR&startDate=2026-10-01&endDate=2026-10-26' \
--header 'x-delbank-api-key: {{apiKey}}' \
--header 'x-delfinance-account-id: {{accountId}}'
```
</RequestExample>
